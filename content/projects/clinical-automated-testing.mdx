## Context

Healthcare applications in daily clinical use at Cloud Data Systems, between July 2024 and August 2025. <Inferred>Production bugs were reaching clinicians, and the applications lacked the test coverage needed to catch them earlier.</Inferred> The documents record the result, not the baseline, so that is inferred from the outcome.

## Constraints

- Tests had to cover both layers of a React Native and Next.js front end paired with Node.js and Spring Boot services.
- The applications were already live: the suite had to be introduced around running software, not before it shipped.

## What I built

Unit and integration tests with Jest, Selenium and Karma, pushing coverage past 90%. Jest covered unit-level behaviour, Selenium drove browser-level integration flows, and Karma ran browser test suites.

<Callout type="note" title="What this page does not claim">
  The published record does not state the baseline coverage, how the 40% reduction in production bugs was counted, or which continuous-integration system ran the suite, so this page does not state them either. No coverage reports or test output appear here because they would reveal client code.
</Callout>

## What changed

- Unit and integration coverage passed 90%.
- Production bugs fell by 40%.
- Critical applications stayed stable under real clinical load.

## Stack

Jest, Selenium and Karma over a React Native, Next.js, Node.js and Spring Boot stack. The deployment side of the same period is covered in the [cloud-native migration](/projects/cloud-native-migration-docker-kubernetes).
