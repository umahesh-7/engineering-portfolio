## Context

The same clinical applications described in the [performance case study](/projects/clinical-performance-optimization) needed a deployment model that could keep up with daily clinical use. <Inferred>Deployments were slower and less reliable than they needed to be.</Inferred> The source documents describe the destination, not the starting point, so that is an inference from the outcome.

## Constraints

- Applications in daily clinical use: downtime is visible to people doing clinical work, so uptime was a hard requirement rather than a nice-to-have.
- Two clouds: the applications ran across AWS and Azure, so the deployment model had to work the same way on both.

## What I built

I deployed Dockerized applications across Azure and AWS via Kubernetes: the applications were containerized with Docker and orchestrated with Kubernetes on both clouds, replacing the previous deployment path with a repeatable one.

## What changed

- Deployment speed improved by 35%.
- Service uptime held at 99% for applications in daily clinical use.
